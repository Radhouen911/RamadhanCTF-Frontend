1. Dynamic Configuration Engine (Core Architecture)The frontend must never hardcode routing or game modes. To ensure stability, the React application will act as a "Traffic Cop," reading the backend configurations on initial load and adjusting the UI dynamically.On initialization, the app must fetch GET /api/v1/configs and store the following key-value pairs in the Global Client State:user_mode: Determines if the game is in "users" (Solo) or "teams" mode.challenge_visibility: Determines if unauthenticated users can view the board.score_visibility: Determines if unauthenticated users can view the standings.2. Routing & Access Control MapThe React Router will conditionally render paths based on the configurations fetched above.A. Core Public Routes (Always Accessible)/: Landing Page (Event details, countdown)./login & /register: Authentication flows./rules & /faq: Static content fetched from CTFd pages.B. Visibility-Dependent RoutesThese routes check challenge_visibility and score_visibility. If set to "Private," they require a valid authentication token to render. If "Public," anyone can view them, but a login prompt must intercept any interaction (like submitting a flag)./challenges: The main gameplay arena./scoreboard: Global standings table and timeline graph.C. Mode-Dependent Routes (user_mode)These routes strictly render based on the active game mode to prevent legacy crashes.RouteBehavior in user_mode: "users"Behavior in user_mode: "teams"/users & /users/[id]Active (Shows individual profiles)Hidden / Redirects/teams & /teams/[id]Hidden / RedirectsActive (Shows team profiles)/team/dashboardHidden / RedirectsActive (Roster, invites, captain tools)Post-Registration FlowRedirects to /challengesForces routing to Join/Create Team3. Component SpecificationsDevelopers must isolate UI elements into the following components to map directly to CTFd API responses.Challenge Board & InteractionChallengeGrid: Container that fetches and displays GET /api/v1/challenges.CategoryGroup: Organizes challenges visually by tags (e.g., Web, Pwn).ChallengeModal: The interactive popup triggered by clicking a challenge. Must contain:MarkdownRenderer: Safely parses challenge descriptions.ArtifactManager: Maps over arrays of downloadable files or links.SubmissionForm: Input field that sends POST /api/v1/challenges/attempt. Must gracefully handle API errors (e.g., "Already solved", "Incorrect flag").SolvesList: A toggleable tab showing first blood and subsequent solves.[OPTIONAL] HintManager & HintBadge: Fetches available hints. If a hint costs > 0 points, clicking the badge must trigger an UnlockConfirmationModal warning the user before sending the POST /api/v1/unlocks request.Team Management (Active only in Team Mode)TeamOnboardingGate: Intercepts users without a team_id and forces them to join or create a team.PrivateTeamDashboard:Displays current team roster.Provides the hidden Invite Token URL.CaptainControls: Conditionally renders if the user is the captain, allowing member removal and team name edits.Scoreboard DataScoreTimelineGraph: Utilizes a charting library (e.g., Recharts) to plot the historical data array provided by /api/v1/scoreboard. Crucial constraint: It must strictly use the API's timeline data to accurately reflect manual admin point adjustments (Awards/Penalties).StandingsTable: Sortable table listing ranks, names, and current scores.4. State Management StrategyTo optimize performance and prevent excessive API calls, state management is split into two layers:Server State (Data Fetching & Caching):Tooling: React Query (TanStack Query) or SWR.Responsibility: Fetches /challenges and /scoreboard. Implements background polling (e.g., every 30 seconds) to update scores and solves dynamically without page refreshes.Global Client State (UI Context):Tooling: Zustand or React Context.Responsibility: Stores authStatus (is the user logged in?), currentUser (ID, name, and team_id), and the global configuration settings (user_mode, visibility statuses) so the Router and Navbar can read them instantly.
